## 自动化复现

在 `frontend` 目录执行。首次安装浏览器测试依赖后运行：

```powershell
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd run test:browser
```

`test:browser` 会先构建并检查浏览器测试类型，再自动启动或复用本机 4173 端口的生产预览。该预览用于测试，不是新增部署。

使用已安装的 Chrome 或 Edge 时，分别在 PowerShell 7 设置浏览器通道后执行：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm.cmd run test:browser

$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm.cmd run test:browser
```

通道无法自动找到浏览器时，可以额外设置 `PLAYWRIGHT_EXECUTABLE_PATH` 为本机浏览器的完整路径；不把本机绝对路径写入仓库配置。`RESPONSIVE_REPORT_PATH`、`RESPONSIVE_OUTPUT_DIR` 可分别指定报告和截图输出目录，避免覆盖前一次结果。

## 用户与实体手机验收

先按 README 启动本机后端，再在电脑打开本地前端。真实接口验证需要自己的虚拟测试账号；自动化 fixture 中的账号不会创建在真实数据库中。

1. 电脑分别用 Chrome、Edge 登录，检查导航、个人资料、记录筛选与翻页，打开一条认领和线索详情。
2. 在注册或资料页输入内容，调整窗口大小，确认输入、验证码倒计时和当前页面状态保持。
3. 手机竖屏打开菜单，进入“我的发布”“我申请的认领”“我收到的认领”“我的线索”，检查信息和操作是否可读、可点。
4. 手机聚焦邮箱、密码及留言输入框，检查系统软键盘弹出后能否滚动至输入和提交区域；横竖屏切换后草稿应保持。
5. 用管理员账号检查管理端表格左右滑动、详情抽屉、会话弹窗与举报处理。需要提交时只使用可变更的虚构测试记录。
6. 记录设备、系统、浏览器版本、操作结果和问题，全部完成后再确认本轮验收。

手机不能用 `localhost` 访问电脑。需要同一可信局域网下的本地预览时，先查看电脑实际 IPv4 地址，将下面的示例地址替换后，在 `frontend` 新终端运行：

```powershell
npm.cmd run build
npm.cmd run preview -- --host 192.168.1.100 --port 4174 --strictPort
```

手机访问对应的 `http://192.168.1.100:4174`。本机后端仍在 8080 端口运行，预览通过已有 `/api/v1` 代理转发。访问不通时检查设备网络和本机防火墙，不修改公网服务器。本轮没有自动开启局域网监听或修改防火墙；测试结束后在该终端按 Ctrl+C 关闭预览。
