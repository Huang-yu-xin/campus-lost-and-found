## 1. B01 无图发布与公开浏览（M2）

- [x] 学生登录后提交物品，后台从会话获取发布人，保存为 `PENDING_REVIEW`，返回物品编号
- [x] 校验标题、描述、地点、日期和常见明文联系方式。失败提示原因，页面保留表单内容
- [x] 公开列表和详情只查询 `PUBLISHED`，待审核记录的公开详情返回 404。公开响应仅展示发布人的公开资料
- [x] 接通发布、列表和详情页面。提交期间锁定按钮，成功显示“已提交，等待审核”
- [x] 新增 3 项集成测试，覆盖审核状态与公开边界、超长标题与联系方式、未登录发布
- [ ] 与甲联调登录和“我的发布”。本人可查看待审核记录，其他学生不能通过改物品编号访问
- [ ] 与丙使用同一物品编号走通管理员审核。审核前访客查不到，审核后能在列表、搜索和详情中看到

**实现与证据**：[物品接口](../backend/src/main/java/com/campus/lostfound/modules/item/controller/ItemController.java)、[查询与写入 SQL](../backend/src/main/resources/mapper/item/ItemMapper.xml)、[页面](../frontend/src/views/item/)、[物品集成测试](../backend/src/test/java/com/campus/lostfound/modules/item/ItemIntegrationTest.java)。测试通过 SQL 设置审核通过后的状态，正式审核流程等待丙的接口。2026-11-06 本机后端 39 项、前端 17 项通过，其中 3 项是乙本次新增用例。乙的代码改动目前在本机工作区，提交编号待记录。

## 3. 发布防重与 B02 图片（M3）

- [ ] 发布防重：同一次提交使用同一提交编号，后台用数据库唯一约束处理并发与重试。相同编号及相同内容返回原结果，不同内容返回冲突
- [ ] 验证连续点击、并发同编号、首次响应超时后重试，每次都检查数据库记录数
- [ ] 独立上传 JPG/PNG，按文件内容判断格式，单张最多 2 MB，每条物品最多 3 张
- [ ] 上传后返回图片编号，待上传成功再提交表单。发布时在事务中校验图片归属并绑定，测试他人图片、重复绑定和第四张图片
- [ ] 校验图片读取权限。待审及其他非公开图片跟随物品的可见性规则，联调丙的审核与认领入口
- [ ] 执行 CT-uploadImage-01、CT-getImage-01，并回归无图发布

## 4. B04 编辑重审与下架（M3）

- [ ] 与甲对齐“我的发布”里的编辑和下架入口，与丙对齐状态、认领约束和并发冲突处理
