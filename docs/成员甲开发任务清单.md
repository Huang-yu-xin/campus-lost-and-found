## 3. A03 邮箱验证码与注册（M2，已完成，提交 ecfe2bf）

后端：

- [x] `EmailSender` 接口 + 开发用实现：把验证码写入 `APP_DEV_MAIL_DIR` 目录，页面和演示中标注“模拟发送”；普通日志和接口响应里都不能出现验证码
- [x] `POST /auth/email-codes`：
  - 用安全随机数生成 6 位验证码，5 分钟有效
  - 数据库只存 `HMAC-SHA256` 摘要（`code_mac`、`key_id`），不存明文
  - 同一邮箱重发时覆盖旧码，60 秒内不能再发
  - 错误次数记在 `failed_attempts`，达到阈值后该码作废
- [x] `POST /auth/register`，在**同一事务**里完成：
  - 校验并消费验证码（只能用一次）
  - 核对名册
  - 写入 `users`
  - 写入两条 `login_identifiers`（学号、卡号）
  - 任何一步冲突都整体回滚，按合同返回 409：`IDENTITY_ALREADY_BOUND`、`ACCOUNT_IDENTIFIER_CONFLICT` 或 `EMAIL_ALREADY_BOUND`
- [x] 邮箱先去掉首尾空白、转小写，再保存和判重；未填昵称时用一个不暴露真实身份的默认昵称
- [x] 注册成功返回 201，**不自动登录**

前端：

- [x] 注册页：发送验证码按钮带倒计时（使用接口返回的 `retryAfterSeconds`），并提示“模拟发送”
- [x] 注册成功后跳转到登录页

测试：

- [ ] CT-sendRegistrationCode-01、CT-register-01
- [x] IT-AUTH-02：验证码错误、过期、已使用时都不能建号；合法请求只建一个账号
- [x] IT-AUTH-03：伪造名册组合或提交 `role=ADMIN` 时返回 400，不会创建管理员
- [x] 学号、卡号、邮箱重复时不留下只建了一半的账号

**证据**：`RegistrationIntegrationTest`（正常注册后用学号或卡号登录、错 5 次作废、过期、60 秒限发、名册不符和 role 字段被拒、重复注册）。CT 合同用例在 A07 正式执行。

## 5. A05 资料、修改邮箱、改密码（M3，已完成，提交 f49e014）

- [x] `PATCH /me`：只能改昵称和手机号；必须带 `expectedVersion`，版本不一致返回 409 `VERSION_CONFLICT`
- [x] **ProfileWorkflowService**（放在 `application` 包，和丙一起完成）：在同一事务中

  - 更新资料

  - 加锁顺序固定为：用户 → 物品 → 认领 → 授权

- [x] `PUT /me/password`：

  - 前端提示用户重新登录
- [x] 前端 `/me/profile` 页面：资料修改、修改邮箱、修改密码

## 已确认的开发决定（2026-11-04，甲确认）

| 事项 | 决定 |
| --- | --- |
| 管理员初始化 | 后端启动时读取本机配置里的管理员账号和密码，还没有该管理员时自动创建；密码不进仓库 |
| 登录限流 | 同一账号连续输错 5 次，锁定 15 分钟后自动解锁，不永久锁号 |
| 验证码错误 | 同一个验证码输错 5 次即作废，需要重新发送 |
| 邮件发送 | 先模拟发送到本机开发收件箱；以后若老师要求真实发送，再接 SMTP |
| 注册邮箱 | 不限制域名；需要时改配置项 |

阈值都写成配置项，以后调整不用改代码。学号、卡号的实际格式仍按合同默认处理（数字学号、ASCII 卡号），等学校真实格式确定后再调整。
