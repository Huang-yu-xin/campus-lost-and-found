# 校园失物招领系统视障友好适配验收记录

## 适配目标与依据

面向使用屏幕阅读器或依赖高对比度显示的同学，让他们能够发现入口、读懂字段和状态，并用键盘操作发布、搜索、认领、线索、举报和管理审核等现有流程。

课程任务书中的控件语义、键盘操作、系统高对比度和功能回归要求落实到浏览器界面。网页实现参考 WCAG 2.2 中的信息关系、对比度、键盘、焦点、错误识别、名称角色值与状态消息条款，弹窗交互参考 WAI-ARIA Authoring Practices 的模态对话框模式。 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [WAI-ARIA 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## 适配说明

- **页面导航**　学生端和管理端均可跳到主内容。进入新页面时更新浏览器标题并将焦点移到主内容，导航的当前位置带有下划线和可访问状态。手机菜单按 `Escape` 收起后返回展开按钮。
- **表单和操作反馈**　为必填字段、留言区、图片选择、筛选和弹窗填写项提供可访问名称。表单提交校验失败时聚焦有误字段，将错误说明关联到输入框。密码可见性可以用键盘切换，读屏可获取按钮的按下状态。搜索、分页、上传和留言使用状态消息反馈结果。
- **列表和弹窗**　管理端及个人记录的表头与数据行由同一张表呈现。窄屏表格的滚动区可聚焦，相关分页区有独立名称。举报、退回和下架的填写弹窗支持键盘导航与关闭，关闭后焦点返回原入口或当前主内容。
- **高对比度**　为键盘焦点、表单边界和当前项补充可辨识的轮廓。用 `forced-colors` 跟随系统对比度主题，当前导航项带有下划线，审核与认领状态带有文字标签。

测试日期为 2026 年 11 月 22 日。桌面环境为 Windows 11 25H2，浏览器为 Microsoft Edge 158.0.4370.33。浏览器端业务流程使用本地构建和模拟接口数据。

| 工具与场景 | 操作 | 实际结果 |
| --- | --- | --- |
| NVDA 2026.3.1，登录页 | 聚焦跳转链接和账号输入框，空表单提交 | 朗读记录包含「跳到主要内容」「账号，编辑框，必填」和「请输入学号、校园卡号或管理员账号」。 |
| NVDA 2026.3.1，物品举报 | 聚焦举报按钮，按 Enter 打开弹窗，再空提交 | 读出「举报物品信息」对话框、举报理由字段和「请填写 1～500 字的举报理由」。 |
| Windows 系统「夜空」对比度主题 | 在系统辅助功能中应用主题，在 Edge 中打开登录和物品列表，按 Tab 移动焦点 | 浏览器检测到强制色。密码显示按钮聚焦时有实线轮廓和按钮边界，物品列表的当前导航保留下划线。 |
