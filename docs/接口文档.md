## 公共规范

- JSON、UTF-8、camelCase；图片上传 multipart/form-data，由浏览器生成 boundary。
- ID 为正整数字符串，如 `"1001"`；前端不转换为浮点数。请求拒绝未知字段，不接受 role、ownerId、senderId 等越权输入。
- 业务日期 YYYY-MM-DD，按 Asia/Shanghai 判断是否晚于今天；时间戳输出带 Z 的 UTC 时间，页面按北京时间展示。
- 文本去除首尾空白后校验长度，按 Unicode 码点计数；前端计数须与后端一致。
- 分页 page 从 1 开始，公开列表每页固定 10 条；其他默认 10、最大 50。超出末页返回空数组。
- 公开列表按 publishedAt、id 降序，个人列表按 createdAt、id 降序，审核待办按 createdAt、id 升序，留言按 createdAt、id 升序。
- 筛选条件 AND 组合；关键词匹配标题 OR 描述，% 和 _ 视作普通字符，不作为 SQL 通配符。
- 所有响应第一版采用 Cache-Control: no-store。日志不记录密码、验证码、联系方式或完整私有留言。

成功使用 HTTP 200 或创建资源的 201，格式为：

```json
{"code":"OK","message":"操作成功","data":{},"requestId":"req-demo-001"}
```

列表 data 包含 items、page、pageSize、total；空结果 items=[]。无额外数据返回 data={}。图片读取是例外，直接返回 JPEG/PNG 二进制。

失败示例，HTTP 409：

```json
{"code":"CONTACT_NOT_ACTIVE","message":"当前认领阶段不允许查看联系方式","data":null,"requestId":"req-demo-002","errors":[]}
```

errors 为字段错误数组，元素包含 field 和 message。客户端根据 code 判断，不依赖 message 文案。失败不能统一包装为 HTTP 200。

| HTTP | 错误码 | 含义 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR、IDENTITY_MISMATCH、EMAIL_CODE_INVALID/EXPIRED/USED、OLD_PASSWORD_INCORRECT、CONTACT_FIELD_MISSING、REPORT_CONTEXT_INVALID | 输入或验证码不合法 |
| 401 | AUTH_REQUIRED、BAD_CREDENTIALS | 未登录、失效或登录凭据错误 |
| 403 | FORBIDDEN、CSRF_INVALID、SELF_OPERATION_NOT_ALLOWED、CONTACT_NOT_AUTHORIZED | 无权操作或尚未授权 |
| 404 | RESOURCE_NOT_FOUND | 不存在或不向当前用户暴露 |
| 409 | VERSION_CONFLICT、IDENTITY_ALREADY_BOUND、ACCOUNT_IDENTIFIER_CONFLICT、EMAIL_ALREADY_BOUND | 版本或唯一性冲突 |
| 409 | ITEM_STATE_CONFLICT、CLAIM_STATE_CONFLICT、ITEM_ALREADY_CLAIMED、CLAIM_ALREADY_EXISTS、CLUE_ALREADY_EXISTS | 状态或重复提交冲突 |
| 409 | CONTACT_NOT_ACTIVE、CONVERSATION_CLOSED、IMAGE_ALREADY_BOUND、REPORT_STATE_CONFLICT | 授权阶段、留言、图片或举报冲突 |
| 413 / 415 | IMAGE_TOO_LARGE / UNSUPPORTED_MEDIA_TYPE | 文件超限或格式不支持 |
| 429 / 500 | RATE_LIMITED / INTERNAL_ERROR | 临时限流或未预期异常 |

## BR-01 会话与 CSRF

使用 JSESSIONID Cookie，不使用 JWT。Cookie 设置 HttpOnly、SameSite=Lax；HTTPS 下启用 Secure。登录轮换会话 ID，退出使当前会话失效；改密草案使该用户全部会话失效。

匿名用户先 GET /auth/csrf，返回 headerName=X-CSRF-TOKEN 和 token。所有写接口，包括注册、验证码、登录，携带该请求头及相应 Cookie。匿名会话不是已登录身份。登录、退出或改密后重新获取令牌。

前端已确定 Vue 3 + TypeScript + Vite + Vue Router + Pinia + Element Plus + Axios。开发时前端 5173 将 /api/v1 代理到后端 8080，路径不重写；优先同源部署或开发代理。不同源时明确允许的具体源和凭据，不使用通配来源加 Cookie。

未登录访问私有业务返回 401；登录后访问他人私有资源统一 404；对可见资源执行无权动作返回 403；非管理员访问管理路径返回 403。CSRF 校验在写入前执行，可优先返回 403。

## BR-02 身份与资料

学号、姓名、校园卡匹配模拟名册；邮箱验证码仅证明邮箱控制权，不冒充真实学校认证。学号与卡号通过统一登录标识表排除跨字段同值导致的登录歧义；预置管理员账号也使用该表。管理员没有学生名册绑定，Me 中 studentId、realName、campusCardNo 返回 null。管理员仅受控初始化，注册不接受角色字段。注册成功不自动登录。

第一版邮箱和登录标识采用 ASCII 字符；邮箱去首尾空白后统一小写保存并判重。学号仍为数字字符串，校园卡实际格式按 P-01 确认。

验证码 6 位、5 分钟有效，绑定用途及邮箱；修改邮箱还绑定当前用户。重发替换旧码，成功使用后原子消费。密码不明文存储。身份字段不可改；昵称与手机号可改，邮箱另走新邮箱验证码流程。联系方式改变时，在同一事务中撤回该用户对应字段的全部授权并递增版本。

## BR-03 可见性与图片

公共接口仅返回 PUBLISHED 物品。其余状态即使发布者登录也不能走公共详情获取，改用 /me/items/{id}。认领和线索双方通过私有详情查看归档后的关联物品。

图片最多 3 张、单张最多 2097152 字节、JPG/PNG，校验真实内容。未绑定图片仅上传者可读；绑定后依物品和参与关系控制访问。存储目录不直接公开，不能绕过接口访问。上传者、物品所有者、相关参与者、审核管理员的具体条件见图片接口描述。

公共物品、申请列表和留言对象不包含手机号、邮箱、真实姓名或校园卡资料。描述、线索和留言禁止直接写联系方式；首版用常见格式检测与提示，物品仍经过人工审核，不能声称正则能识别所有变体。

## BR-04 物品状态

| 当前状态 | 动作 | 新状态 | 条件 |
| --- | --- | --- | --- |
| 无 | 发布 | PENDING_REVIEW | 登录、字段与图片归属合法 |
| PENDING_REVIEW | 管理员通过 | PUBLISHED | 设置本次 publishedAt |
| PENDING_REVIEW | 管理员退回 | RETURNED | 原因必填 |
| PENDING_REVIEW / RETURNED / PUBLISHED | 本人编辑 | PENDING_REVIEW | FOUND 无认领历史，LOST 无线索历史，类型不变 |
| PENDING_REVIEW / RETURNED / PUBLISHED | 本人下架 | OFF_SHELF | FOUND 无已确认申请，关闭其他进行中关系 |
| PUBLISHED | 标记找回 | ARCHIVED | 仅 LOST，closureReason=FOUND |
| PUBLISHED | 完成交接 | ARCHIVED | 仅 FOUND，有对应 CONFIRMED 申请，原因 HANDOVER |
| PUBLISHED | 管理员违规下架 | OFF_SHELF | 选做，原因 VIOLATION，关闭关系与授权 |

第一版不提供恢复上架或重新打开。存在认领/线索历史后禁止编辑是本轮草案，需与需求说明书同步。

## BR-05 认领状态

仅 FOUND、PUBLISHED、无确认人时可申请。不能认领自己发布的信息，说明至少 10 字。同一用户对同一物品最多一个申请，包含驳回/关闭历史。

| 当前状态 | 动作 | 新状态 | 同步结果 |
| --- | --- | --- | --- |
| 无 | 提交 | PENDING | 双方可留言，发布人收到申请 |
| PENDING | 发布人确认 | CONFIRMED | 唯一认领人，其他待确认申请 CLOSED/OTHER_ACCEPTED |
| PENDING | 发布人驳回 | REJECTED | 原因必填，不可重提 |
| CONFIRMED | 发布人完成交接 | COMPLETED | 物品归档，授权失效，停止发送留言 |
| PENDING | 本人下架物品 | CLOSED | 原因 OWNER_WITHDRAWN |
| PENDING / CONFIRMED | 管理员违规下架 | CLOSED | 原因 VIOLATION，授权失效 |

CLOSED 为本轮系统关闭状态建议，不等于发布人判断凭证不实。首版不增加取消确认、转移认领人或重开申请。

## BR-06 简化线索

仅 PUBLISHED 的 LOST 可收线索，发布人不能给自己提交。每用户每物品最多一条，后续留言补充。内容 10～500 字，无图片、无关联招领编号，无批准或驳回流程。

内容仅双方可见，多条线索可以并存。查看不表示线索有效。发布人无须已有线索也能标记找回；找回或关闭后历史可查，停收线索和留言，不影响其他招领信息。

## BR-07 联系方式授权

已确认规则：CONFIRMED 后可授权，COMPLETED 后失效。

1. 授权范围为当前认领中的另一方。双方分别操作自己的手机号、邮箱，默认 false；线索首版不开放授权。
2. PUT 提交 phoneVisible、emailVisible、expectedVersion；首次版本 0，两开关 false 即撤回。目标对象由服务端推导，不接受用户编号。授权前该字段必须存在。
3. 查询自己的设置不含真实资料，终态可返回 effective=false。查询对方资料必须同时满足认领 CONFIRMED、物品 PUBLISHED、对应字段获准且存在。
4. 无关用户返回 404；有效阶段但未获授权返回 403 CONTACT_NOT_AUTHORIZED；阶段无效返回 409 CONTACT_NOT_ACTIVE。
5. 完成交接事务同时清空双方授权并递增授权版本。读取仍须校验业务状态，不能只信任旧开关。资料变化也撤回对应字段授权。
6. 只返回当前获准字段，未获准字段省略。响应 no-store，页面在流程结束/撤回后清理展示值。
7. 撤回只能限制后续访问，无法收回对方此前已看到或已收到的数据。

授权请求示例：

```http
PUT /api/v1/claims/3001/contact-permission
Content-Type: application/json
X-CSRF-TOKEN: <当前会话令牌>
Cookie: JSESSIONID=<当前会话>
```

```json
{"expectedVersion":0,"phoneVisible":true,"emailVisible":false}
```

对方查询成功时 data 可以为 `{"claimId":"3001","phone":"<授权手机号>"}`，不含 email。完成交接后再次查询必须失败。

## BR-08 留言

认领 PENDING、CONFIRMED 且物品 PUBLISHED 时可发；线索提交后且寻物仍 PUBLISHED 时可发。终态保留历史、禁止新增。同物品的其他申请人不是这条会话的参与者。

首版普通 HTTP 请求，不增加实时推送或通知中心。“收到申请/线索”通过个人记录列表实现，不承诺实时通知。

## BR-09 事务和并发

- 更新物品、认领、举报携带目标资源 expectedVersion；不一致返回 VERSION_CONFLICT，成功递增。
- 确认认领必须有物品级行锁或原子条件更新，不能只检查单条申请版本；同时确认不同申请只能一个成功。
- 交接完成时，申请、物品、双方授权、审计记录同事务提交或回滚。
- 授权更新与交接完成采用一致锁顺序，完成后迟到的授权请求不能重新打开权限。
- 联系方式读取与完成操作要有明确串行化点：完成提交后的新查询不得返回资料；已经获准发出的响应不能撤回。
- 线索创建与寻物归档协调同一物品状态；归档后的新增提交失败。
- 唯一索引保证身份、itemId+applicantId、lostItemId+providerId 等约束，不能只“先查后插”。

具体锁与事务需实际 MySQL 集成测试证明，禁用按钮不等于并发控制。

## BR-10 举报与管理员边界

管理员角色不自动获得所有私有会话的读取权。举报绑定物品，可再绑定一个认领或线索上下文；提交人须为该会话参与者，且上下文属于该物品。普通无上下文举报只针对当前公开可见物品。

管理员仅通过待处理举报的 conversation 接口查看对应凭证与留言，记录谁、何时、因何举报读取了哪个上下文；无上下文 404，已处理 409，不包含联系方式。

处置包括 KEEP、TAKE_DOWN、REJECT_PENDING_CLAIM。驳回仅限关联 PENDING 申请；已确认不能直接回退。业务处置与举报结论同事务，冲突时全部不修改。
